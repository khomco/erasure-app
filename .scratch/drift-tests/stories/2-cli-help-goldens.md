## Intent

**Problem:** Nothing pins what `wipestation --help` and each subcommand's `--help` print, so a renamed or dropped flag, a changed default, or a removed subcommand ships with no test noticing — and W2.2's generated CLI reference has no committed input to build from (SPEC CAP-2).

**Approach:** An integration test in `wipe-cli` runs the built `wipestation` binary, discovers every subcommand from the binary's own help output (recursively), and compares each one's `--help` text with a committed golden under `docs/generated/cli/`; `UPDATE_GOLDENS=1` rewrites them (CAP-5).

## Boundaries & Constraints

**Always:** Subcommands are discovered from the binary's help output, never from a hand-kept list in the test. Output comes from running the real binary (`env!("CARGO_BIN_EXE_wipestation")`) with an emptied environment, so a caller's `WIPESTATION_*` variables or terminal cannot change it. One golden per command path, named `wipestation[-<sub>...].txt` (e.g. `wipestation-license-issue.txt`), including the top level `wipestation.txt`; contents are exactly the binary's stdout. A golden file in `docs/generated/cli/` that no command produces fails the test; under `UPDATE_GOLDENS=1` it is deleted and the rest rewritten. A missing golden fails with the regeneration command in the message. CRLF checkouts compare equal.

**Never:** No change to CLI flags, help text or behaviour. No new crate, xtask, CI config, `sites/` or Astro (D1). No new dependencies, including dev-dependencies. The hub binary (`wipe-hub`) is out of scope. Do not touch `docs/generated/http-routes.txt` or `route_golden.rs`.

## I/O & Edge-Case Matrix

| Scenario | Input / State | Expected Output / Behavior | Error Handling |
|----------|--------------|---------------------------|----------------|
| In sync | Binary and goldens agree | Test passes | — |
| Help text changed | A flag's doc comment or default edited | Fails naming the golden file and the first differing line (number, golden, produced) | Message shows `UPDATE_GOLDENS=1 cargo test -p wipe-cli --test help_golden` |
| Subcommand added | New `Cmd` variant, no golden | Fails naming the missing golden | Same regen command |
| Subcommand removed | Golden left for a gone command | Fails naming the stale file | Same regen command |
| Regenerate | `UPDATE_GOLDENS=1` | Goldens written (dir created), stale ones deleted; plain re-run passes | — |
| Caller env set | `WIPESTATION_STATIC_DIR=/x` in the test's env | Output identical to unset | — |
| Nested commands | `license` has its own `Commands:` list | `license new-root`, `license issue`, `license inspect` each get a golden | — |
| Built-in `help` | `help` listed under `Commands:` | Not treated as a subcommand | — |

## Autonomous decisions

- **What counts as "every subcommand".** The station's command-line tool has nested commands (`license issue`). Options: (a) only first-level commands; (b) every command path, plus the top-level listing. Chose (b): the success criterion says "every subcommand", nested ones carry most of the flags, and the top-level listing is what catches a removed command.
- **Where the subcommand list comes from.** Options: (a) a hand-written list in the test; (b) the binary's own `Commands:` sections. Chose (b): the SPEC's point is that code-derived reference cannot drift, and a hand list would itself drift.
- **Stale goldens.** When a command is removed, its golden would otherwise sit in `docs/generated/cli/` forever. Chose to fail on it and have `UPDATE_GOLDENS=1` delete it — the directory then always equals the binary's command set, which is what the docs site will consume. Only `*.txt` files in that one directory are considered.
- **Header line.** The route golden starts with a `# Generated by …` line. Help goldens do not: their content is exactly what a user sees, ready to paste into a reference page; the regen command lives in AGENTS.md and the failure message.

## Design Notes

Discovering commands from help text rather than clap's `Command` tree is forced: `Cli` lives in a binary crate, which integration tests cannot import, and testing the binary is the user-facing surface anyway. Parsing target (clap 4 default template):

```
Commands:
  serve        Run the Axum API server ...
  license      Vendor licensing tools (ADR-0005)
  help         Print this message or the help of the given subcommand(s)
```
